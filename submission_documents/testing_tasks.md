## Manual Testing Task Division

Every one of the 127 features in [`features_list.md`](features_list.md) is
assigned below to the member whose domain it falls into, grouped by that
document's own 26 categories so a tester can work through it category by
category with the feature numbers open side by side. This replaces the
previous six-bullet-per-member sketch with a checklist that actually covers
the full list.

Rows 1–14 cover features 1–97. Rows 15–25 were added when the features list
was extended to 127 and cover features 98–127. Every feature number falls in
exactly one row, and the ranges quoted in the two tables below cover 1–127
with no gap. The single deliberate repeat is the unnumbered accessibility row,
which re-tests #95 from the other member's side and says so.

Several of the new rows need **Options > Debug Mode** switched on before the
surface they test exists at all — the dev panel, the cheats panel and their
`F2`–`F11` shortcuts are all gated behind it. Switch it back off before any
run whose score is meant to count: turning on a cheat taints the run, and a
tainted run deliberately writes no high score and unlocks nothing (**#107**),
so a tester who leaves it on will read that as a save/achievement bug.

### Cross-cutting: play at least one full session together

However the two domains above are split, finish with one full co-op or
versus session played together end to end (Main Menu → a full level → Victory
→ World Map → a second level → Game Over or campaign clear), so at least one
manual pass exercises the transitions between every system in this table
rather than each system in isolation.
