# Verifies R17 item 3 (D18): an enemy killed by a fireball should flip about
# the AABB's vertical centre line, not its bottom edge.
#
# Uses level_1.json TEMPORARILY edited: spawnPoint at (118,19), directly under
# the FireFlower question block at (118,17) (QuestionBlock::Content::FireFlower
# = itemType 2, confirmed in QuestionBlock.hpp); the goomba at (112,20) shoved
# to (195,20) so only the one at (115,20) is in play as the fireball target;
# and the tiles at (115,17) and (117,17) changed from brick to coin_tile (both
# are TileType per TileMap.cpp — Coin is non-solid, Brick is solid) to widen
# the one-tile passable gap already at (116,17) into a three-tile one. All
# reverted before commit.
#
# Why the tile edit: this block is flanked by solid brick at y=17, and a jump
# straight up under it only bumps it from below — the block is solid on top
# too, so the ejected FireFlower item (which sits statically on top, one tile
# up, per FireFlower.cpp's permanent zero velocity — unlike the Star test's
# item, which bounces down to the player) can't be reached that way. Clearing
# the block's top requires rising through the passable gap and drifting
# sideways into the item while still airborne. A one-tile gap, and then a
# two-tile gap, both left too little margin against ordinary frame-timing
# jitter between runs (confirmed empirically across repeated attempts: the
# same scripted inputs landed Mario short of the flower in some runs and
# touching it in others). Widening to three tiles — purely to make an
# unrelated, pre-existing platforming reach feasible for a scripted replay,
# not a change to anything the fix touches — gives enough margin to land the
# crossing reliably.
#
#   ./build/SuperMarioGame --script tests/scripts/verify_r17_fireball_flip.txt
#
