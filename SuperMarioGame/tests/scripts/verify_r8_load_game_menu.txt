# R8 live verification (D-load-game-menu): drives Game::run()'s real loop
# through Start Game -> a level -> Pause -> Save Game -> Quit To Menu -> the
# new LOAD GAME row -> confirming a slot -> back into a live, loaded level.
#
# Caveat, stated up front rather than glossed over: the pause menu's SAVE GAME
# row (PlayingState.cpp's PauseState callback) has always saved to whatever
# Game::getInstance().getActiveSlot() currently is, and nothing reachable by
# keyboard alone changes that away from its default of 1 — only DevPanel's
# per-slot Save button (ImGui, mouse-driven) can target slot 2/3 directly, and
# this input-script harness only synthesises keyboard events (see
# InputScript.hpp's grammar). So this run saves to and loads from SLOT 1, not
# slot 2 — same generic loadFromSlot() path, a different slot number. Slot 2
# specifically is covered by tests/verify_frontend_states.cpp's
# testLoadGameRestoresPlayerFromSlot(), which saves and loads slot 2
# programmatically through the identical PlayingState(...,/*pendingLoadSlot=*/2)
# constructor path MenuState's LOAD GAME confirm uses.
#
#   ./build/SuperMarioGame --script tests/scripts/verify_r8_load_game_menu.txt
#
