#
# Main menu rows (current dev HEAD, after R8 inserted LOAD GAME): START=0,
# LOAD=1, VERSUS=2, DAILY=3, EDITOR=4, GENERATOR=5, RECORDS=6, OPTIONS=7,
# QUIT=8. Two Down presses from START reaches VERSUS/MULTIPLAYER (NOT one —
# see the note filed against tests/scripts/versus_cpu.txt, which still assumes
# the pre-R8 layout and lands on LOAD GAME instead).
#
# MatchConfig defaults to GameMode::VersusHuman (MenuState.hpp:89) with a HUMAN
# opponent (m_match.isCpuOpponent() false), so opening the Multiplayer page and
# going straight to START — without touching MODE or OPPONENT — starts a real
# two-human match on World 1-1 (levelIndex 0), both players controlled by this
# process's own two key sets (config.json: P1 left/right/jump/fire = A/D/W/F;
# P2 has no keyBindings2 override, so InputManager's built-in P2 defaults apply
# — Left/Right/Up/Period, confirmed in InputManager.cpp's loadDefaultBindings
# and resetBindingsToDefaults, which R21 made agree. This line used to say M;
# 1a7a6db moved P2 fire off M because M is the minimap toggle, and the reset
# table was not updated with it, so the two disagreed until R21.)
#
# The death: Player 2 is walked straight into the Goomba at level_1.json's
# (x:12, y:20) — 9 tiles from the (x:3, y:19) spawn — WITHOUT ever jumping. A
# side touch on a Goomba is not a stomp, and Player::powerDown() (Player.cpp)
# publishes PlayerDied the instant a Small player is hit with no power to lose.
# No positional feedback is needed for this: it is a straight line, a known
# distance, and a script that never presses jump for P2 cannot land on the
# Goomba's head by accident. Player 1 is left standing at spawn throughout.
#
#   ./build/SuperMarioGame --script tests/scripts/verify_r12_versus_human_death.txt
#
# Screenshots land in saves/shots/. The death itself is also confirmed on
# stdout: PlayingState prints "[PlayingState] Respawned. Lives remaining: N"
# (or "Game Over" if the last life) from Player::powerDown()'s PlayerDied,
# which only P2's own hit can have triggered here.
