## Issues & Resolutions

### **Issue 1: ObjectPool Zero-Allocation Particle Recycling**
* **Problem**: Naive particle systems allocate and deallocate `Particle` objects on every emission burst, causing heap fragmentation and GC-like pauses during high-density particle events (e.g., 50+ coin sparkles simultaneously).
* **Resolution**: Implemented `ObjectPool<Particle>` with a pre-allocated fixed-capacity vector. `acquire()` returns a pointer to an inactive pooled particle (O(1) linear scan of active flags), and `release()` marks the particle inactive without deallocation. Pool capacity is set at initialization and never grows, ensuring zero heap allocations during gameplay.

### **Issue 2: Player Sprite Atlas Coordinate Boundary Extraction**
* **Problem**: Source sprite sheets contained variable-sized frames with inconsistent padding, making automated frame boundary detection unreliable for generating JSON frame descriptors.
* **Resolution**: Implemented boundary detection scanning for non-transparent pixel regions within atlas grid cells, with configurable padding tolerance thresholds. Generated `player.json` with 92 validated frame rectangles mapped to animation state identifiers.

### **Issue 3: Uniform Real Random Distribution for Particle Spread**
* **Problem**: Using `rand() % range` for particle velocity spread angles produced non-uniform distributions with visible clustering artifacts in radial emission patterns.
* **Resolution**: Replaced with C++17 `std::uniform_real_distribution<float>` seeded from `std::random_device` via `std::mt19937`, producing visually uniform radial particle spread patterns.
