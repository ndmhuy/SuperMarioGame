02

Engine bug: you could not jump while walking into a wall

Fixed
Knowledge
CollisionResolver's wall-slide rule zeroed vertical velocity on a purely horizontal collision (normal (−1, 0)), guarded by onGround — a flag the X pass always sees as false because the Y pass that recomputes it runs later in the frame.
Implementation
Character::wasOnGround (frame-start state) as the airborne test; upward-momentum kill removed; downward slide cap kept. Found via --trace: vy −678.8 applied → erased same frame, 8700 frames straight.
Outcome
level_1 10.8→31.8%, level_2 13.8→47.8%. Agent went from frozen (0 deaths) to genuinely playing. 14/14 ctest, verified in the running game.

04

level_3: the 4-tile wall is mathematically unclimbable

Maths finding
Knowledge
The engine integrates with semi-implicit Euler at 60 Hz: gravity is added to velocity before the position step. That loses exactly half a frame of launch velocity versus the continuous parabola.
Maths
v0        = √(2·g·h)  = √(2·1800·128)          = 678.82 px/s
continuous apex      = v0²/(2g)                = 128.0 px  (exactly 4 tiles)
discrete rise        = Σₖ (v0 − k·g·dt)·dt      k = 1..22, dt = 1/60
                     = 128 − v0·dt/2 (+O(dt²))  = 122.4 px = 3.82 tiles
4-tile ledge (128px) > 122.4  →  impossible, misses by 5.6px every time
3-tile ledge  (96px) < 122.4  →  clears with 26.4px margin
above-ledge window (3-tile): 678.8t − 900t² = 96 → t ∈ [0.19, 0.57] s
Tech stack
eval_level --trace full jump cycle; Constants.hpp (GRAVITY 0.5 px/frame² × 3600, JUMP_HEIGHT 128).
Outcome
apex box-bottom = 517.6px   ledge top = 512px   missed by 5.6px, deterministically
descent clamped to +50 px/s  (wall-slide cap — correct behaviour)
Reasoning

The trace matched the discrete formula to the pixel — the agent's jump is perfect and insufficient. Consequences: (a) the oracle's tile-rounding (round(y/32)) grants up to half a tile of phantom height and violated its own lower-bound contract — logged as its open defect; (b) the intended route must use the falling platform at (41,19) or the question blocks at (36,16)/(40,16) — elevated launch points, which a purely reactive policy never routes through.

05

bonus_1: the pipe the agent cannot see

Root cause
Knowledge
Levels carry solid things two ways: tiles in the tile map, and entities (pipes, question blocks, moving/falling platforms — all EntityCategory::Block). Physics collides with both. scanEnvironment's entity pass handled Enemy/Item/Projectile and skipped Block on the false belief the tile pass covered them.
Tech stack
AIController::scanEnvironment (vision grid), Entity::getCategory(), level JSON ({type: pipe, x:58, y:19}).
Outcome
agent box edge 1856.0 = 58·32, grid says right=Empty, reason="advancing", 190s
→ the wall it is pressing into does not exist in its perception
Reasoning
This is a perception bug, not a decision bug: the policy is behaving correctly for the world it is shown. Fix perception, not the policy. It also matters beyond the heuristic — every logged RL observation had the same blindness, so this is a data-quality fix for training too.
06

Fix: solid entities enter the vision grid · observation contract v2

Shipped
Implementation

EntityCategory::Block → Solid (question blocks → Reward, mirroring the tile pass), painted across the entity's full tile footprint — a 2×2 pipe previously would have marked only its centre cell, leaving the face the agent collides with unmarked.

kAIObservationVersion 1 → 2: layout unchanged, semantics extended. Cells that always read Unknown/Empty now carry information, so v1-trained weights would misread every level with a pipe — the version gate refuses them by design.

Reasoning
Bumping the contract now is free (no trained weights exist yet); not bumping it would have planted the hardest-to-diagnose failure the RL doc warns about — a policy acting confidently on misaligned inputs.
07

Fix: the policy learns the physics envelope, and how to give up

Shipped
Knowledge
From step 04: climbable ⇔ wall height ≤ 3 tiles. Jumping at a 4-tile wall is provably futile; the only local move that changes anything is leaving.
Maths
escape   = 80 decisions @ 60 Hz ≈ 1.3s ≈ 6 tiles at walk speed
stuck    = 120 decisions (2s) with |vx| < 0.05·RUN_SPEED → escape regardless of cause
Implementation
wallHeight() (consecutive solid cells above foot level, 0–4) gates the wall-jump; raisedGroundAhead() labels edge-jumps toward higher ground; an escape state reverses direction when pinned at an unclimbable wall; a generic stuck detector escapes after 2s of no horizontal motion whatever the cause. reset() clears all of it.
Reasoning
The stuck detector is deliberately cause-blind: the wall trigger covers the trap that was understood; the timer covers the ones that were not — which step 09 promptly proved necessary.

09

bonus_1 again: the koopa-shell bounce-lock

Emergent trap
Knowledge
Stomping gives a fixed −300 px/s bounce and does not ground the player. Player::jump() requires ground contact (or coyote frames).
Maths
bounce apex = Σₖ (300 − 30k)/60 , k=1..10  =  22.5 px
pipe top    = 64 px above the floor        →  bounce can never clear it
grounded    = never                        →  canJump never fires
Outcome
vy: +240 → −300 → decay → +240 → −300 …  x = 1832.0 for 168 s
a stationary shell wedged against the pipe; the agent bounces on it forever
Reasoning
No wall rule can see this — the obstacle is kinematic, not geometric. Exactly the case the cause-blind stuck detector (step 07) exists for: 2s at x=constant → escape.
10

Harness fidelity: death reloads the level, as the game does

Shipped
Knowledge
The real game reloads the level on death. The harness respawned only the player — so level_3's one-shot falling platforms stayed consumed and its trough became a lava-walled dead end the real game never presents. Fitness was scoring a level that does not exist.
Tech stack
eval_level.cpp: LevelLoader re-load on death; AIController binds the player by reference, so the controller is rebuilt via std::optional::emplace around the fresh player; reward banked across lives so the report stays whole-run.
Outcome
bonus_1: 46.4% → 13.1%, 59 deaths — one identical death every 3.4s
Reasoning
The fidelity fix was correct and it exposed a truth: with ε=0 the Hard agent is fully deterministic, and identical world + identical policy = the same first death repeated forever. The old 46.4% was partly luck rented from a corrupted world (enemies staying dead between lives). Honest numbers got worse; the measurement got right.
11

Two speed gates, tried and reverted — with numbers

Reverted
Knowledge
The repeated death: the agent jumps at a 2-tile block while at run speed — the 1-tile lookahead triggers at fixed distance, so at 300 px/s the arc peaks past the block and dives into the pit behind it. Mid-air run acceleration (vx 150→300 during flight) stretches it further.
Maths
deceleration: 1000 px/s² normal ground,  250 px/s² on ice
→ "jump only at walk speed" is unsatisfiable on ice: the agent can never slow down
Outcome
                       lvl_1   lvl_2   lvl_3   bonus_1
frozen baseline         24.9    75.3    21.4    13.1
+ jump-speed gate       14.3    12.4    22.0    40.7   ← ice breaks it
+ no-run-in-mid-air      8.4     1.9    39.7    60.6   ← reshuffles, not repairs
Reasoning

Each gate traded two levels for two others. That is not noise — it is the signature of a chaotic plateau: a reactive policy rides knife-edge deterministic trajectories, and any parameter nudge reshuffles which knife-edge fails. Both gates reverted; the measured numbers are recorded in-code so the loop is never re-walked.

This plateau is the concrete, measured case for the RL policy — a learned policy trains on the distribution of situations instead of hand-tuned trigger distances, which is precisely what the IAIPolicy seam exists to host.
