Geometric solvability oracle — measure the level, not the player

Floods a level with every jump the engine's own physics constants permit. No policy, no agent. Difficulty as a bottleneck: the hardest forced move on the kindest route.

level                required  optional  reachable   0.25s/level
level_1                 0.71      0.96    100%
level_2                 0.96      0.96    100%
level_3                 0.96      0.96    100%
bonus_1                 0.71      0.81    100%
level_*_sub             0.14      0.42    100%

The levels are provably fine. So the agent was the problem — and a playthrough-based fitness function, which is what every system in the literature uses, cannot tell those apart. It also flagged two design faults no playtest had found: level_2 and level_3 require a jump at 96% of the physical maximum, and difficulty is a cliff, not a curve.

Ruled out the obvious suspects

Each checked rather than assumed: AABB::intersects uses strict comparisons, so exact tangency is not a false collision. The 0.01px pushback at x=775.99 is ordinary wall resolution. The cell above the agent is empty, and no entity sits within 96px.

Instrumented the physics engine — root cause

The jump velocity was already gone before the Y pass ran. The X pass was destroying it, on a collision whose normal has no vertical component at all.

[phys ] preVelY=0  y 577.99 -> 577.99  collisions=0

09

The fix — two defects in one rule

One: the airborne test read onGround, which PhysicsEngine clears at the start of each frame and only recomputes in the Y pass — which runs after the X pass this code lives in. It read false for a character standing firmly on the ground, so the rule fired for everyone touching a wall. Character now keeps wasOnGround.

Two: it cancelled vertical velocity because a wall was touched. A wall is vertical; rising alongside one is ordinary platforming, and a real ceiling is the Y pass's job. Only the downward slide cap survives.

include/Entities/Character.hpp     + wasOnGround
src/Physics/PhysicsEngine.cpp      capture before clearing onGround
src/Physics/CollisionResolver.cpp  the rule itself
Fixed
