## Issues & Resolutions

### **Issue 1: EventBus Subscriber Listener Sentinel Bug on Unsubscribe**
* **Problem**: When unsubscribing an EventBus listener handle in `PlayingState`, invalid handle checks using raw integer comparisons caused out-of-bounds array access or missed listener removals.
* **Resolution**: Updated `EventBus` subscriber handle sentinel representation to `static_cast<size_t>(-1)` to safely handle invalid or unsubscribed listener IDs across event broadcasts.

### **Issue 2: Stale Toast Rendering on Achievement Reset / Reload**
* **Problem**: Loading a saved slot or invoking `setUnlockedAchievements()` did not clear active visual toast notifications in `AchievementManager`, causing previously unlocked toasts to pop up continuously after reloading a save.
* **Resolution**: Added explicit `m_activeToasts.clear()` inside `AchievementManager::setUnlockedAchievements()` and `reset()` to flush stale toasts prior to loading new slot states.

### **Issue 3: Save Slot Out-of-Bounds Flagpole and Spawn Point Coordinates**
* **Problem**: Saving game state when player coordinates were out-of-bounds or near edge boundaries wrote raw negative or out-of-range floats into save slot JSON files, causing crash or invalid position loading.
* **Resolution**: Added `MathUtils::clamp` coordinate verification inside `Serializer.cpp` and `LevelLoader.cpp` to bound spawn points and flagpole coordinates strictly within level dimensions before JSON serialization.

### **Issue 4: EntityFactory Constructor Mismatch for Concrete Entities**
* **Problem**: Instantiating derived entity classes in `EntityFactory::createEntity` using default constructors (`make_unique<T>()`) failed to compile because `Mario`, `Luigi`, `Toad`, `Peach`, and item subclasses require explicit position parameter constructors (`sf::Vector2f position`).
* **Resolution**: Updated `EntityFactory` switch-case factory methods to pass the target `position` argument explicitly to every concrete class constructor.
