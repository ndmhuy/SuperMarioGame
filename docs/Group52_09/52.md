## Issues & Resolutions

### **Issue 1: Non-Solid Coin Tiles Not Collected on Walk-Through**
* **Problem**: `TileType::Coin` has `TileInfo::isSolid = false`. `CollisionDetector::checkEntityVsTileMap()` only reports solid tile collisions, so walking through grid-placed coin tiles failed to trigger coin collection — coins remained rendered permanently on the grid.
* **Resolution**: Added non-solid interactive tile pickup detection in `PhysicsEngine::update()`. After physics integration, the engine scans the player's bounding box footprint against the tile grid. When any overlapping tile is `TileType::Coin`, it is collected (+1 coin, +200 pts, `coin.wav` SFX) and the grid cell is cleared to `TileType::Empty`.

### **Issue 2: Fireball Event Listener Lifecycle & Player Exit Cleanup**
* **Problem**: `PlayingState` subscribed to `PlayerShotFireball` events via `EventBus` but did not unsubscribe the listener handle when exiting the playing state, causing dangling callbacks and potential use-after-free when the event was published after state destruction.
* **Resolution**: Added explicit `EventBus::unsubscribe()` calls in `PlayingState` destructor and `InputManager::unregisterPlayer()` to cleanly detach all event listeners and input bindings when exiting the playing state.

### **Issue 3: Time Rewind Key Conflict with Run Modifier**
* **Problem**: Initial implementation mapped time rewind to `Left Shift` / `Right Shift` keys, conflicting with the run speed modifier binding, causing Mario to simultaneously sprint and rewind.
* **Resolution**: Separated rewind trigger to dedicated `R` key. Added a magenta semi-transparent HUD banner reading "⏪ REWINDING" to provide clear visual feedback during active rewind.

### **Issue 4: Game Crash on Window Close (Mutex Lock Failure)**
* **Problem**: Closing the game window during active gameplay caused a mutex lock failure in `GameStateManager` because state destructors attempted to access already-shut-down singleton managers (`SoundManager`, `AchievementManager`).
* **Resolution**: Updated `Game::shutdown()` to explicitly pop all remaining game states from the `GameStateManager` stack *before* shutting down singleton managers, ensuring state cleanup runs while all manager dependencies are still alive.
