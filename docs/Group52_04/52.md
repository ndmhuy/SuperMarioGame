## Issues
* **Issue 1**: Standard item collision resolution in the physics engine automatically cancels all velocity components along the contact normal, which prevented moving items (like Mushrooms and Stars) from bouncing or reversing direction on contact.
  * **Resolution**: Implemented custom collision check heuristics inside each item's update loop. If the horizontal velocity is zeroed, the item reverses its direction. If the vertical velocity is zeroed (for the Star), it bounces back up.
* **Issue 2**: Encapsulated protected member variables of the player character could not be modified by interactive items (like the Trampoline spring) due to C++ visibility constraints.
  * **Resolution**: Added a public `setVelocity()` method in the base `Entity` class, allowing external controllers and interactive objects to modify velocity vectors safely while preserving encapsulation of internal position/boundingBox attributes.
